三、核心API接口清单（RESTful）
产品源模块
1.  POST /api/product/crawl  传入1688链接，抓取商品，生成主表记录
2.  POST /api/product/manual/create  手动录入商品
3.  GET /api/product/master/list  商品主列表
4.  GET /api/product/master/{id}  获取单条主商品详情
5.  PUT /api/product/master/{id}  修改主商品，自动升级version版本
调度核心模块
6.  POST /api/task/create  创建任务（抓取/图片处理/适配/上传）
7.  GET /api/task/list  任务列表，查看执行状态
8.  POST /api/task/retry/{task_id}  失败任务手动重试
9.  POST /api/task/cancel/{task_id}  取消任务
平台适配器层
10.  POST /api/adapt/generate_draft  输入master_id+platform，执行字段适配，生成平台草稿，写入product_platform_rel
11.  GET /api/adapt/platform_draft/{rel_id}  查询适配后的草稿报文，给前端预览
出口（审核发布）
12.  GET /api/audit/pending/list  获取待审核草稿列表
13.  POST /api/audit/submit  审核通过/驳回，写入audit_record
14.  POST /api/publish/execute/{rel_id}  发布门接口：必须校验权限，审核通过才允许调用，正式提交平台
15.  GET /api/publish/result/{rel_id}  获取发布结果
AI大脑模块
16.  POST /api/ai/check_text  文本违规检测
17.  POST /api/ai/gen_title  AI生成标题
18.  POST /api/ai/image_process  图片抠图、尺寸裁剪、水印检测

from abc import ABC, abstractmethod
class BasePlatformAdapter(ABC):
    def __init__(self, shop_cfg):
        self.shop_cfg = shop_cfg # 店铺授权、类目映射配置
    @abstractmethod
    def read_master_product(self, master_data):
        &quot;&quot;&quot;读取商品主表数据&quot;&quot;&quot;
        pass
    @abstractmethod
    def translate_fields(self, master_data):
        &quot;&quot;&quot;字段翻译：主表字段 → 平台请求字段&quot;&quot;&quot;
        pass
    @abstractmethod
    def check_required(self, platform_payload):
        &quot;&quot;&quot;校验平台必填项，缺失返回错误&quot;&quot;&quot;
        pass
    @abstractmethod
    def upload_images(self, image_list):
        &quot;&quot;&quot;上传图片到平台素材库，返回平台图片ID数组&quot;&quot;&quot;
        pass
    @abstractmethod
    def submit_draft(self, payload):
        &quot;&quot;&quot;提交生成草稿，返回平台草稿id&quot;&quot;&quot;
        pass
    @abstractmethod
    def publish_draft(self, draft_id):
        &quot;&quot;&quot;草稿正式上架&quot;&quot;&quot;
        pass
每个平台适配器继承这个基类，只重写内部逻辑；调度层统一调用基类方法，实现“共用动作序列，平台值分开”。
五、调度核心任务拆分（celery任务）
1. crawl_task
- 输入：source_url
- 输出：product_master一条记录
- 内置：文字闸初步过滤，遇到违禁直接标记作废，不再往下流转
2. image_process_task
- 输入：master_id
- 逻辑：下载原图 → 水印检测 → AI处理图片 → 本地缓存
- 失败：记录错误，任务状态置失败，可重试
3. adapt_task
- 输入：master_id + platform
- 逻辑：加载对应适配器 → read_master → translate_fields → check_required → upload_images → submit_draft
- 输出：写入product_platform_rel，状态=draft
4. publish_task
- 输入：rel_id
- 前置校验：查询audit_record必须有审核通过记录；校验发布权限；否则直接拒绝执行
- 调用adapter.publish_draft()
- 更新platform_status、error_msg
断链续跑逻辑：任务表记录 next_run_time ，程序启动扫描：status=0/1 并且 next_run_time &lt;=now 的任务继续执行。
六、合规“三道闸”逻辑
1. 文字闸 text_filter
- 词库文件： ban_word.txt ，每行一个违禁词
- 扫描：title、desc、attrs
- 命中 → master.status=5作废，写入日志，不再向下派发任务
2. 图片闸 image_check
- 水印检测、简单logo特征匹配
- 发现严重水印/侵权标记 → 任务终止，标记待人工处理
3. 业务校验闸
- price &lt; cost_price * 0.3 价格异常拦截，禁止自动发布，进入人工审核队列
七、异常、重试、熔断规则
1. 网络超时、平台限流：指数退避重试，最大重试3次
2. 返回业务错误（类目不存在、属性非法）：不可重试，直接标记失败，等待人工修改主商品
3. 某平台连续10个任务失败 → 触发熔断，暂停该平台全部新任务；后台告警，人工恢复
4. 任何步骤失败，不修改原始product_master数据，错误写在product_platform_rel.error_msg，保证主表安全。

九、风险点内置处理（写进代码逻辑）
1. 平台API变更：适配器和业务主逻辑隔离，只修改对应adapter，不改动调度、主表
2. 多店铺：platform_config按shop_id隔离配置，不同店铺密钥互不干扰
3. 防止重复上架：抓取时对比source_url历史记录；适配时对比平台item_id
4. 数据安全：平台access_key、secret全部加密存储，不明文返回接口
